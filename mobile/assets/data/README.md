# Offline Philippine address data

`ph_psgc.json` is the app's bundled Region → Province → City/Municipality →
Barangay hierarchy plus a default postal code for each city/municipality.

- **Source:** [`@aivangogh/ph-address`](https://www.npmjs.com/package/@aivangogh/ph-address)
  version `2026.2.4`, MIT licensed.
- **Underlying classification:** Philippine Standard Geographic Code (PSGC),
  Philippine Statistics Authority, as of 30 June 2026.
- **Generated by:** `mobile/tool/generate_ph_psgc.js`. Do not hand-edit the JSON;
  re-run the generator when the upstream snapshot changes.

The generator resolves the PSGC shapes the picker does not expose:

- NCR is province-less. Its 17 localities hang directly off the region and the
  app displays `Metro Manila` as the province label.
- Manila's 14 sub-municipal districts are folded into `Manila City`.
- Isabela City (PSGC orphan `0990101000`) is grouped under Basilan, matching the
  postal table's mailing label.
- The eight BARMM Special Geographic Area municipalities (parent `1999900000`)
  are exposed as a synthetic `Special Geographic Area` province under BARMM.
- Sulu follows the package's current Region IX placement (the 2024 Supreme Court
  ruling removed Sulu from BARMM).

Postal codes are the municipality-level default. A city with a central post
office and district codes uses the lowest/CPO code; the form keeps the field
editable because a buyer's own barangay can have a different code.

The app deliberately does **not** reverse-geocode coordinates. The optional
location pin saves latitude/longitude for the location preview only; the buyer
still chooses region/province/city/barangay from this offline catalogue.
